# Phase 3 — ONNX CPU deployment preparation

## Verified scope and current blocker

Production now defaults to ONNX Runtime CPU and the real public artifact:

- HF repository: `ThanhHai25/TomatoCare-UniRepLKNet-A`
- File: `best_unireplknet_a.onnx`
- Input: one `float32 [1,3,224,224]`; output: one `float32 [1,4]` logits tensor.
- One Uvicorn worker; one ONNX intra-op thread, one inter-op thread, sequential execution.

The owner reports Kaggle parity on 12 validation images with maximum absolute logit error **8.106e-6**. Owner-reported Kaggle figures: Default peak RSS 108.76 MB / mean latency 28.63 ms; Low Memory peak RSS 90.42 MB / mean latency 91.33 ms. These are Kaggle measurements, not Codex measurements or evidence of latency at Render's 0.1 CPU. The exact settings of the owner's Low Memory benchmark were not supplied; this implementation's options are documented below rather than assumed identical.

Codex still receives **HF HTTP 403**. The full-API benchmark attempted the real download and reported **blocked**, **0 successful predictions**, no inference latency, and **88.90 MiB startup peak process RSS**. That RSS includes the failed startup, not a loaded model or inference. No real trained inference has been verified here, and operation under the complete Render Free 512 MB / 0.1 CPU budget is not yet confirmed. Tests use clearly isolated synthetic weights/HTTP fixtures; production has no mock mode or random-init fallback.

## Local production-style ONNX setup

Use Python 3.12 and Node 22/24. From the checkout root, create a fresh environment:

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -r backend/requirements.txt
CORS_ORIGINS=http://localhost:5173 ONNX_PROFILE=default \
  python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000 --workers 1
```

The requirements have seven direct dependencies: FastAPI, Uvicorn, python-multipart, Pillow, NumPy, huggingface_hub and ONNX Runtime. No PyTorch, torchvision, timm, training packages, database or paid API is required. The isolated tested environment occupies approximately **219 MiB on disk including package tooling**; this is not RAM usage. Existing training/research requirements remain separate.

The predictor/session is loaded once at startup and reused. Model initialization failures result in `/health` and `/predict` returning 503, with an actionable error. Nothing silently substitutes another model. To use a trusted local copy when downloads are unavailable:

```bash
ONNX_MODEL_PATH=/actual/path/best_unireplknet_a.onnx \
CORS_ORIGINS=http://localhost:5173 \
python -m uvicorn backend.main:app --port 8000 --workers 1
```

Set `MODEL_REVISION` to the HF commit containing the ONNX file for reproducibility. `main` is the initial default; no revision lacking this newly uploaded ONNX is assumed. `MODEL_REPO_ID` and `ONNX_FILENAME` are configurable. The model identifier includes its actual file SHA-256. Public model access does not require a token.

### Labels, preprocessing and metadata

The confirmed checkpoint logit order is **Healthy, Early Blight, Late Blight, Leaf Mold**; it is never alphabetically sorted. Input processing is EXIF orientation correction, RGB, PIL bilinear resize exactly 224×224, scaling to [0,1], and ImageNet normalization (`mean=[0.485,0.456,0.406]`, `std=[0.229,0.224,0.225]`). Batch size is always one. Input/output dimensions and float type are checked when constructing the session; invalid tensors/logits are rejected.

If the ONNX contains `class_names` and `preprocessing` JSON custom metadata, the loader reads and validates them. If it does not contain metadata, it uses the model owner's confirmed checkpoint contract above. This is explicit configuration, not fallback weights or invented predictions. Incomplete or contradictory embedded metadata fails initialization.

An optional local `ONNX_METADATA_PATH` can point to `inference.json` generated by the research exporter, together with `ONNX_MODEL_PATH`. Its artifact hash and parity report must match. **No sidecar is required or automatically downloaded for the owner's validated public ONNX file.** `/health` reports which metadata source was used.

### Default and Low Memory

`ONNX_PROFILE=default` is preferred: `ORT_ENABLE_ALL`, memory pattern and CPU arena enabled. Both thread counts are fixed to one even if an unrelated `CPU_THREADS` variable is larger.

`ONNX_PROFILE=low_memory` disables CPU arena and memory pattern and uses `ORT_ENABLE_BASIC`. It is a selectable alternative, not an automatic model change or a guarantee of lower memory on every host. Benchmark this exact profile on the target service if needed. Neither profile changes weights, image resolution, preprocessing or label order.

## Frontend / Vercel PWA

```bash
cd frontend
npm ci
VITE_API_URL=http://localhost:8000 npm run dev
```

`VITE_API_URL` is the API origin, without `/predict`. It is public build-time configuration. The client posts the real selected image as multipart `file` to `${VITE_API_URL}/predict`, validates the four-class probability response, and uses no API/user-image caches. Missing configuration produces a clear error. Request timeout is 120 seconds with retry; network errors and HTML 502/503/504 cold-start responses explain that the free service may be starting. The four-screen React design has not been changed.

For Vercel Hobby: import the reviewed repository, choose Root Directory **frontend**, Vite preset, Install Command `npm ci`, Build Command `npm run build`, Output Directory `dist`. Set `VITE_API_URL` to the actual Render HTTPS origin before building. Changing it requires rebuilding. `frontend/vercel.json` is already prepared. Never put secrets in Vite environment variables.

The PWA precaches static assets only. An installed shell can reopen offline, but AI analysis requires a network connection. Photos/results are not deliberately stored in service-worker caches, localStorage or IndexedDB. Camera uses the native `capture="environment"` input; real-device permission and Add to Home Screen behavior still need a phone check. Desktop automation verifies the capture attribute and file selection, not physical camera hardware.

## API contract and privacy

- `GET /health`: 200 when the ONNX session is ready, otherwise 503.
- `POST /predict`: valid JPG/PNG multipart `file`, up to 10 MiB; also rejects corrupt images and unsafe dimensions above 20 megapixels. EXIF and RGB are normalized. One prediction at a time; a busy service returns 429.
- Response: `predicted_class`, `confidence`, probabilities for all four classes, `model_identifier`, `inference_ms`. Softmax is computed from real model logits.
- No persistent image store; temporary multipart files are closed. API responses use `Cache-Control: no-store`.
- `CORS_ORIGINS` accepts explicit comma-separated approved frontend origins, never `*`. Examples contain only local development values, not invented production URLs. CORS is not authentication.

```bash
curl -f http://localhost:8000/health
curl -f -F 'file=@/actual/path/leaf.jpg' http://localhost:8000/predict
```

`.env.example` files document process settings; the Python backend does not implicitly load `.env`. Checkpoint and environment-secret files stay outside Git.

## Render Free — native Python preferred

`render.yaml` now defines a native Python **Free** Web Service; Docker is optional. Use the repository root as the service root and Python 3.12.14. Commands:

```bash
# Build Command
pip install --no-cache-dir -r backend/requirements.txt
# Start Command (Render provides PORT)
uvicorn backend.main:app --host 0.0.0.0 --port "$PORT" --workers 1
```

The Blueprint sets ONNX, Default profile, one-thread environment settings and `/health`. Set `CORS_ORIGINS` to the actual Vercel HTTPS origin; pin `MODEL_REVISION` when the appropriate HF commit is known. No paid tier/database/GPU is required. Check a real `/predict` after readiness and test cold starts; an HTTP server with 503 health is not ready.

`backend/Dockerfile` remains an optional ONNX-only packaging path, with one worker and `${PORT:-8000}`. Prior Docker build attempts in Codex were blocked by Docker build-container DNS/proxy resolution. The native Render configuration does not depend on that build path. No Render or Vercel deployment has been executed.

## Benchmark the complete API process

Run with a real accessible model and a leaf image in the isolated ONNX-only environment:

```bash
python -m scripts.benchmark_api --image /actual/path/leaf.jpg --profile default --runs 10
python -m scripts.benchmark_api --image /actual/path/leaf.jpg --profile low_memory --runs 10
```

The command starts one real Uvicorn process, waits for readiness, sends HTTP uploads and reads Linux high-water process RSS, including FastAPI imports, session, HTTP and image decode. It reports startup, per-request/mean latency and successful request count. A download/readiness failure exits nonzero with `status=blocked`; any recorded memory is then **failed-startup-only**, and no latency is invented. Use `--port` if the default 8765 is occupied. The model-only research benchmark remains `python -m scripts.benchmark --runtime onnx --image ...`.

Process RSS is not container/cgroup memory. Test repeated HTTP requests, initialization, upload parsing and rejected concurrent requests on the actual constrained service. Leave headroom under 512 MB; Kaggle CPU timings do not establish latency on 0.1 CPU. Free instances may sleep and redownload into an ephemeral cache. Do not claim free-host readiness until real artifacts pass these checks.
